# How to Synchronize Dotfiles Across Multiple Machines

This guide explains how to synchronize your development environment and configuration files across multiple computers (such as a workstation, laptop, and remote server) using MountSync.

---

## Overview

A common challenge in multi-machine setups is managing configuration differences:
- A laptop may need lighter power management scripts and Wi-Fi configurations.
- A workstation may require multi-monitor display configurations and heavier development toolchains.
- A remote server requires server-specific utilities while omitting GUI application configs.

MountSync manages multi-machine setups using a centralized cloud vault, `sync-map.conf` manifests, and tags/groups filtering.

---

## Workflow Overview

```text
Machine A (Source)                         Cloud Storage                        Machine B (Target)
+-------------------+                      +-------------------+                +-------------------+
| ~/.bashrc         |  mosy add            | Vault Storage     |  mosy init     | ~/.bashrc (link)  |
| ~/.config/nvim/   | -------------------> | (Google Drive/S3) | -------------> | ~/.config/nvim/   |
| (Local files)     |                      | sync-map.conf     |                | (Replicated links)|
+-------------------+                      +-------------------+                +-------------------+
```

---

## Step 1: Set Up the Primary Machine (Machine A)

1. Install MountSync and configure your cloud remote:
   ```bash
   curl -sL https://raw.githubusercontent.com/GabrielTeixeiral0l/MountSync/main/install.sh | bash
   ```

2. Add your dotfiles to MountSync, assigning appropriate tags and groups:
   ```bash
   # Add shell configs common to all machines
   mosy add ~/.bashrc -g dotfiles -t common,shell

   # Add Neovim config tagged for development machines
   mosy add ~/.config/nvim -g config -t dev,editor

   # Add workstation-specific monitor layouts
   mosy add ~/.config/monitors.xml -g config -t desktop
   ```

3. Confirm files are registered:
   ```bash
   mosy list
   ```

---

## Step 2: Provision a New Machine (Machine B)

On your second computer (e.g. your laptop or work machine):

1. Install MountSync and connect it to the **same** cloud storage remote during setup:
   ```bash
   curl -sL https://raw.githubusercontent.com/GabrielTeixeiral0l/MountSync/main/install.sh | bash
   ```

2. Verify that the cloud vault is mounted:
   ```bash
   mosy status
   ```

3. Initialize your dotfiles based on the machine's role.

### Option A: Full Initialization (`mosy init`)

`mosy init` reconstructs all managed symbolic links recorded in `sync-map.conf`. If a local file already exists at a target location, MountSync safely creates a timestamped backup (`.bak_YYYYMMDD_HHMMSS`) before linking:

```bash
mosy init
```

### Option B: Selective Initialization by Tag or Group

To provision a machine with only a subset of configurations (e.g. only development and common shell tools, omitting desktop layouts):

```bash
# Initialize only items tagged with 'common' or 'dev'
mosy init --tag common,dev

# Initialize only items belonging to the 'dotfiles' group
mosy init --group dotfiles
```

### Option C: Non-Destructive Update (`mosy pull`)

If you want to link newly added cloud items without touching or backing up existing local files:

```bash
# Link only missing items
mosy pull

# Filtered pull
mosy pull --tag common
```

---

## Step 3: Handle Multi-Environment Profiles

If your work machine requires completely isolated configurations from your personal computer, use MountSync Profiles:

```bash
# On work machine, use the 'work' profile
export MOSY_PROFILE=work

# Add work-specific configuration
mosy add ~/.gitconfig -t work

# On personal machine, use the 'personal' profile
export MOSY_PROFILE=personal
mosy add ~/.gitconfig -t personal
```

You can compare configuration divergence across profiles using `mosy diff`:

```bash
mosy -p work diff ~/.gitconfig -c personal
```

---

## Step 4: Conflict Resolution & Disaster Recovery

### Automatic Safety Backups

When `mosy init` encounters an existing physical file at a target path (e.g. a default `~/.bashrc` generated by the OS installer), MountSync renames the existing file:

```text
Backing up /home/user/.bashrc to .bashrc.bak_20260823_143000...
Creating link for .bashrc...
```

### Inspecting Conflicts with `mosy diff`

Compare your current synced version against the backup to merge any machine-specific tweaks:

```bash
mosy diff ~/.bashrc -b
```

### Restoring Local Originals

If you ever need to stop synchronizing an item on a specific machine and revert it to a standalone local file:

```bash
mosy remove ~/.bashrc
```

---

## Step 5: Offline Durability & VFS Caching

MountSync utilizes `rclone` with VFS caching (`--vfs-cache-mode writes` or `full`).

- **Offline Reads/Writes**: When your laptop is offline, you can continue modifying your dotfiles normally. Changes are recorded in local VFS cache (`~/.cache/rclone`).
- **Reconnection Sync**: When network connectivity is restored, `rclone` automatically uploads pending writes to your cloud provider.

## Cross-Platform Sync (Linux, macOS, and Windows)

If you are synchronizing configurations across different operating systems with divergent file paths (such as VS Code settings in `~/.config/Code/...` on Linux, `~/Library/Application Support/Code/...` on macOS, and `%APPDATA%/Code/...` on Windows), use the dedicated [`mosy link`](cross-platform-sync.md) command.

For a complete step-by-step recipe, consult the [Cross-Platform Synchronization Guide](cross-platform-sync.md).
